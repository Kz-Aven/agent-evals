# templates 使用说明

本目录存放**执行结果和评分的参考案例**，用于对齐输出风格、证据粒度与脱敏标准。
评分或记录前，先挑一个业务形态最接近的案例对照；不要照抄结论，只对齐写法。

## 案例索引

| 案例 | 文件 | 看点 |
| --- | --- | --- |
| 案例 A：销售通话分析专员 | `案例A-销售通话分析专员-任务执行链.md` | 数据分析类任务的 10 步执行链：技能加载、数据授权、数据源缺失恢复、统计脚本、HTML 报告、执行链自交付 |
| | `案例A-销售通话分析专员-能力评分.json` | 单份 FAIL 评分（65 分）：样本量 86 与分类合计 88 的数学矛盾如何被写成证据 |
| | `案例A-销售通话分析专员-多轮评分汇总与产品决策.md` | 5 轮汇总：汇总表 → 维度表 → 总体指标 → 失败模式聚类 → 能力定位与产品决策 |

| | `案例B-PPT知识助理-能力评分.json` | 单份 PASS 评分（84 分）：素材溯源、卖点证据、QA 覆盖、效率的扣分写法 |

## 脱敏约定（写执行链与评分时必须遵守）

| 公司名 / 品牌名 / 客户名 | xx公司、xx品牌、xx客户 |
| 内部系统、平台、数据源 | xx数据平台、xxCRM |
| 数据表 ID、记录 ID | `<表ID-已脱敏>` |
| 竞品名 | 竞品A、竞品B |
| 内部域名、OSS 链接 | `<内部链接-已脱敏>` |
| 技能名 / 工具名 | 保留原名（不属于敏感信息） |
| 时间区间、数值、条数 | 保留原值（是可复核性的基础，不得改动） |

## 使用方式

- **写执行链时**：对照同形态案例，检查字段是否齐全（Action / Skill / Tool / Arguments / Result / Error / Recovery / Final Answer / Execution Summary）。
- **写评分时**：对照案例 JSON，检查每个 `failures` 项是否都带可观察证据，数值是否复算过。
- **写汇总报告时**：对照 `案例A-销售通话分析专员-多轮评分汇总与产品决策.md` 的章节结构与"证据支持的结论 / 待验证假设"区分方式。
